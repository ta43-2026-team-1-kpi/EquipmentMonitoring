# ADR 0005. Grafana поверх PostgreSQL з окремою роллю тільки для читання

**Статус:** прийнято

## Контекст

pgAdmin зручний для адміністрування, але не показує стан обладнання в динаміці. Для моніторингу потрібні графіки показників і попереджень у часі. Окремий збирач метрик для цього не потрібен: усі дані вже лежать у базі.

## Рішення

- Grafana з джерелом даних PostgreSQL і дашбордом, що описані в репозиторії (`grafana/provisioning`, `grafana/dashboards`). У самій Grafana їх не редагують (`editable: false`, `allowUiUpdates: false`).
- Grafana підключається як `grafana_reader`:
  - тільки `SELECT`;
  - `default_transaction_read_only`;
  - `statement_timeout = 10s`.
- Роль створює одноразовий ідемпотентний сервіс `grafana-db-init` після міграцій API; `ALTER DEFAULT PRIVILEGES` покриває таблиці з майбутніх міграцій. Створювати роль у міграціях застосунку не можна: це інфраструктура середовища, а не схема застосунку.
- Для демонстрації є `simulator` (профіль `demo`). Він шле показники через публічний API, як справжній шлюз датчиків, і змінює лише межі власного обладнання, не чіпаючи глобальні.

## Наслідки

- Помилка в запиті дашборда не може змінити дані або довго тримати навантаження на базі.
- Запити дашборда залежать від схеми бази. Якщо перейменувати таблицю чи колонку, треба оновити `equipment-monitoring.json`; CI перевіряє, що дашборд завантажився і джерело даних працює.
- Стек моніторингу опціональний і не впливає на базовий і продакшн-запуск.
