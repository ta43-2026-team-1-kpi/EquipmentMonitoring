# ADR 0003. Паролі як Docker secrets

**Статус:** прийнято

## Контекст

У базовому стеку паролі передаються змінними середовища з `.env`. Їх видно через `docker inspect` і в `/proc/<pid>/environ`, вони потрапляють у діагностичні дампи, а рядок підключення API містить пароль відкритим текстом.

## Рішення

- Кожен пароль лежить в окремому файлі `secrets/<name>.txt` і монтується як Docker secret у `/run/secrets/<name>`. Каталог `secrets/` є в `.gitignore` і `.dockerignore`.
- PostgreSQL і pgAdmin читають паролі через `*_FILE`, Grafana — через `GF_*__FILE` і `$__file{}` у provisioning. pgAdmin підключається до бази через `PasswordExecCommand`.
- API читає рядок підключення без пароля зі змінних середовища, а пароль — із файлу, вказаного в `Database:PasswordFile` (`PostgresConnectionString.Resolve`). Якщо файл відсутній або порожній, API не стартує і пише зрозумілу помилку.
- Паролі генерує `scripts/new-secrets.ps1`. Наявні файли без `-Force` не перезаписуються, бо зміна файлу не міняє пароль у вже ініціалізованій базі.
- Обов'язкові несекретні змінні перевіряються синтаксисом `${VAR:?message}`.

## Наслідки

- Жоден пароль не потрапляє в оточення контейнерів. Це перевіряє `verify-stack.ps1`.
- Без swarm Compose монтує secrets як файли з хоста, тож права доступу визначає файлова система хоста. Для навчального стеку на одному хості цього досить.
- Щоб змінити пароль PostgreSQL, треба виконати `ALTER ROLE` і оновити файл.
